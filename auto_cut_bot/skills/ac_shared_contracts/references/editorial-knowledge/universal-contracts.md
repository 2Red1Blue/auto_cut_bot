# 通用合同 — 跨类型底层规则

所有剧种共用以下三份底层合同。类型适配器（`*-v1.json`）只决定主线优先级、支线功能和高光/高潮形式，不得覆盖连续性、结尾和防幻觉要求。

## continuity_contract — 连续性

- 开头、中间、结尾必须服务同一条 `primary_story_thread_id`
- 混剪回溯只能解释开场前因、人物关系、故事背景或规则/动机
- 回溯后必须重新回到主线向前推进
- 跨段连接必须有 causal、time、same_scene、theme、source_transition 或 visual_transition 证据

## ending_policy — 结尾落点

- 优先在同一主线的未完成 Hook 处结束
- 没有真实、合适的 Hook 时，允许在当前故事线的集尾结束
- 不得编造悬念
- 不得在已有 Hook 后接入未来完整剧情弧

## duration_extension_policy — 时长延展

- 不足 300 秒时，从最后选段的源时间点向后顺剪
- 先到当前集尾，仍不足才按集号从下一集 0 秒继续
- 达到 300 秒后继续到达到门槛所在集尾
- 延展必须保持同一主线、严格向前、无重复、无无功能填充
- 证据不足就停止延展并进入复核

## interpretation_rules — 解释规则

1. `integrated_support` 不是普通可删除支线。只有重复且不改变关系、动机、主线助力或设问兑现的内容才可压缩。
2. "保留"不等于"补写"。必须同时满足结构功能和真实 Event/Fact/Thread Beat 证据。
3. 黄金样例的具体人物、集号、时间码和龙族设定不可迁移；只能迁移判断规则。
4. 负面样例只用于回归测试和失败路由，永远不能作为当前项目剧情证据。
5. 每条成片只加载 Bible 路由选中的 `golden_case_ids`；类型未知、置信度不足或证据为空时，停止自动套用并进入人工审核。
