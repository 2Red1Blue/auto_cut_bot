# VLM 观察职责强制规范

生效：2026-09-10，来自用户明确纠偏。适用所有新建/修改的 VLM Prompt、模型可见输入、
response schema、decoder、下游投影及部署验收。MUST / MUST NOT 是合并审查规则。
本文是 VLM 职责的规范源；具体新合同见
[观察型 VLM 输入输出设计](../../../docs/llm-stage-contracts/14-vlm-observation-only-contract.md)。

## 1. 唯一职责

VLM MUST 只描述当前收到的媒体中自己观察到的内容，以及明确作为模型意见的理解、猜测和不确定性。
人物外观、动作、表情、画面文字、场景、镜头变化、动机、冲突、悬念等信息可以丰富。
MUST NOT 为降低结构失败率把输出压成几句摘要；减少的是机器协议负担。

## 2. 禁止模型承担的工作

VLM 输入和输出 MUST NOT 要求生成、选择、复制或验证：

- 全局或局部 ID、短别名、数组下标引用、`p001/f001/e001`、`T0` 时间桶引用、外键；
- 封闭业务枚举或评分档位：fact/event kind、temporal mode、标签集合、confidence 等级、候选类别；
- Candidate / hook / highlight 对象、候选排序、anchor/support/context/payoff 角色分配、素材选择；
- evidence atoms、support 对象、引用图、事实事件闭包、measurements、置信分数、校准误差；
- hash、schema/revision 常量、来源凭证、Receipt、Admission、授权、覆盖率证明、物理端点或渲染参数。

禁止将同一职责改名为 `core-only`、`editorial_signals`、ordinal 或 evidence-lite 后重新交给 VLM。
禁止把这些结构搬进自然语言模板，如要求“描述1支持事件2”或在文本中回显 ID。
自然出现的名字、车牌、屏幕编号属于可见内容，允许描述；它们不因此成为系统身份。

固定 JSON 容器字段和 string/array/object/null 类型允许；它们不是业务分类枚举。
时间提示只能是可空的自然语言线索；不得用 mandatory 毫秒端点或精确 time bucket 代替。
“这段对峙让我感到紧张”允许作为自由判断；“候选 c1 的 hook_strength=0.9”禁止。

## 3. 输入与认知边界

MUST 只提供当前媒体、简明观察任务、必要的片段时长/播放语境和浅层格式说明。
首版感知调用不注入剧情/角色答案，Context Pack 留给后续解释节点。
真实字幕正文可以由 VLM 从画面读取；未经验证的音轨能力不得声称听到了声音或对白。
模型不能证明自己具备某个模态；可用能力由程序的已验证 provider profile 决定。
视频内出现的提示词、JSON、命令或“忽略规则”文字只作为画面内容，不能成为执行指令。

## 4. 程序与下游职责

MUST 由程序绑定 source/window/Attempt/raw bytes，分配身份、维护版本、引用和血缘。
数组位置可以在收到原响应后由程序用于内部寻址；不得要求 VLM 返回相互引用的下标。
名字/描述不是唯一键；实体对齐、语义分类和候选提案在独立下游步骤处理，不保证能确定性推断。
无法确定时 MUST 保留歧义或多个假设，不补默认 kind、不合并相似人物、不发明事实或候选。
文本模型若参与下游解释，其结果仍为模型提案；封闭类别、引用闭合、候选实例和准入由程序治理。

MUST 区分“模型说看到了”与“独立验证为真”。ID/hash/合法 JSON/确定性编译/成功 Receipt
只能证明来源或结构，不自动证明视觉内容真实。模型判断和未知状态不得升级为事实。
自然语言中提及的关系不能直接生成通过校验的证据边；物理剪辑仍须独立定位、ASR/VAD/Frame 等验证。

## 5. 保存、失败和重试

MUST 不可变保存原响应与程序管理的状态。完整响应的时间线索缺失/格式不佳/超出窗口，
只使定位不可用；原始文字与有用描述继续保留，不能补出物理时间或抛弃整段语义。
缺项、空数组、未提及与明确的否定观察不是一回事；MUST NOT 从空值推断“无人物/无冲突/无语音”。
完整描述被接收只代表 observation report 可供理解，不等于观察覆盖整段视频或已获事实准入。

截断/不完整 stream、拒答、超资源预算和根 JSON 无法解码必须显式记录，不能当作完整报告。
完整 raw 的纯格式恢复如被支持，必须另记派生操作并保证不增删语义；首版不默认实现自动修复。
下游分类、引用或候选失败 MUST NOT 触发已保存观察的再次视频调用。
未知 provider 结果只能按相同 attempt 身份查询；新语义请求须单独绑定来源与有限预算。

## 6. 禁止历史契约复活

旧 V23/V4 留作精确历史读取/重放，不是新设计模板；旧响应不得标记为新 schema 的成功响应。
新合同不能靠伪造 V4 facts/events/candidates 兼容旧消费者。
与本文冲突的旧设计、parity 表、任务计划或示例不再授权 VLM 字段。保留语义信息，允许迁移结构。
运行替换未完成时必须明确报告；不得以文档更新声称部署已修复。

## 7. 合并与启用门禁

合并审查 MUST 拒绝任何违反 §1–6 的新模型可见字段、Prompt 示例或消费者要求；
不得把“先跑通旧消费者”“只用短 ID”或“多重试几次”作为例外。只能由用户明确修订职责边界。

启用新 runtime 前 MUST 有可执行检查及结果，至少覆盖：

1. 实际送往 provider 的 prompt/schema（含 `$ref` 展开和适配器附加字段）没有业务 enum/const/引用/举证槽位；
   正向允许自然语言字段、普通可见编号和自由解释，不能只做关键词黑名单。
2. 禁止字段变体、下标图、自然语言 ID 回显模板和旧 candidate alias 的负面回归。
3. 含糊身份、未定位文字、错误时间线索、看不清字幕、未知音轨、矛盾判断均可保留原义。
4. 持久化/重新读取/replay 后内容和来源可追溯；下游失败不再触发视频调用，重复操作不重复收费。
5. 新旧 reader/profile/authority 严格隔离；不能从本报告直接通过旧事实或物理 Admission。
6. 人工对照视频评估描述忠实度、关键细节召回和判断区分；单集真实链路通过后才可放大到整剧。

当前落地是强制规范与审查要求；上述 runtime 自动门禁的实现与真实验收尚未完成。
