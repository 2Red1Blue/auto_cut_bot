# Normal CUDA Runtime Activation

## Goal

An operator starts the FunASR service in normal mode without hand-authoring a
profile.  The Pipeline alone decides whether that live service may produce
timed evidence, using the accepted CalibrationRecord in PostgreSQL.

## Authority split

```text
protected static CalibrationPolicy
        + live RuntimeMeasurementIdentity
        -> shadow raw evidence
        -> independent validation
        -> accepted CalibrationRecord in PostgreSQL
        -> Pipeline resolver + live normal identity comparison
        -> timed-evidence request admitted
```

`CalibrationPolicy` remains the immutable source/installed-local-run policy.
It specifies model family, corpus, timing semantics and acceptance limits.
`RuntimeMeasurementIdentity` is generated by the running service and contains:

- audit-only `build_audit_sha256`;
- derived `timing_compatibility_sha256` and its complete reproducible inputs;
- measured native protocol identity and the two exact producer identities.

The audit hash is retained in the record and receipts but never decides ordinary
reuse.  The compatibility hash is the normal admission key.

## Required wire and persistence changes

1. Add a closed `runtime_measurement_identity` member to raw shadow evidence.
   The independent replay verifies it against the authenticated service response
   and refuses a response whose compatibility hash or producers differ.
2. Add `timing_compatibility_sha256` and runtime-identity digest to
   `CalibrationRecordIdentity`; bump only the calibration-record schema and add
   a forward-only database migration. Old records cannot satisfy CUDA normal
   mode and remain historical/auditable.
3. Extend the accepted-anchor read so the Pipeline receives both values from the
   immutable accepted record, not a caller-supplied environment variable.
4. In normal mode the service self-measures the same runtime identity as shadow
   mode. It exposes the authenticated loopback identity endpoint but returns
   timed evidence only for a request carrying the exact accepted record digest
   and matching timing compatibility hash.
5. The Pipeline asks PostgreSQL to resolve the installed local-run authority,
   compares its accepted record to the live service identity, and creates the
   request. A mismatch is `recalibration_required`; it never degrades to an
   uncalibrated transcription.

## Explicit non-goals

- The FunASR container does not receive PostgreSQL credentials or decide record
  acceptance itself.
- A health-check success, raw shadow response, audit-hash equality, or a caller
  supplied hash is not normal-mode authority.
- No existing accepted CPU record is rewritten to claim CUDA compatibility.

## Tests

- Audit-only change preserves compatibility and normal admission.
- Model/CUDA/device/decoder/timing-policy change blocks normal admission.
- A forged request hash or record digest is rejected by the service.
- A PostgreSQL reader returns only the exact accepted aggregate/validation pair.
- Normal Pipeline start fails with an actionable `recalibration_required`
  outcome when no compatible record exists.
